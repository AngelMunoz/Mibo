# Fix raylib shadow pass instancing + add LayeredGrid3D

## Summary

Two framework changes developed while validating the Platformer3D sample:

### 1. Fix raylib shadow pass to use instanced rendering (ForwardPbrPipeline.fs)

**Problem:** `collectMeshDraws` unrolled every `DrawMeshInstanced` command into individual `MeshDraw` entries — one per instance. With ~900 instanced terrain cells per chunk × 9 visible chunks, this produced ~8,100 individual `Raylib.DrawMesh` calls into the shadow map every frame. The MonoGame backend never had this issue because it already keeps instanced draws as single entries (`ShadowPass.fs:ShadowInstancedDraw`).

**Fix:** Added `InstancedMeshDraw` struct (mirrors MonoGame's `ShadowInstancedDraw`). `collectMeshDraws` now collects `DrawMeshInstanced` commands as single entries in a separate pooled `InstancedMeshDraw[]` array. `renderShadowRegion` renders them via `Raylib.DrawMeshInstanced` (one GPU call per entry). This collapses ~8,100 individual shadow draws → ~18 instanced shadow draws. Both arrays are `ArrayPool`-returned in the `finally` block.

**Verified:** 393 raylib tests pass. In-game FPS restored from ~40 to ~115 with instanced-heavy 3D terrain.

### 2. Add LayeredGrid3D (LayeredGrid3D.fs)

Cubic layered grid wrapping `CellGrid3D`, mirroring the existing `LayeredGrid2D` (2D) and `LayeredHexGrid3D` (hex 3D) patterns. ~30 lines, mechanical mirror of `LayeredHex3D.fs`. Provides `LayeredGrid3D.create`/`getOrAddLayer` and `LayeredLayout3D.layer`.
